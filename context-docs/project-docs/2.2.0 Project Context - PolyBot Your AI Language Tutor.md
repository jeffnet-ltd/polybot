## Executive Summary

PolyBot is an **AI-powered multilingual language learning platform** combining a structured **10-module CEFR A1 Curriculum** with AI roleplay for "True Bilingual" learning (target language + native language explanations).

**Current Status (v2.2.0):** Complete A1 curriculum. All LLM inference has moved off the local machine to a **RunPod Serverless GPU endpoint**. The database has moved from local Docker MongoDB to **MongoDB Atlas**. The backend FastAPI server no longer loads any ML model on startup — it is now a lightweight API server that forwards prompts to RunPod and reads/writes to Atlas.

### Key Architectural Change: Local Model → RunPod Serverless

In v2.1.x, the FastAPI backend loaded Llama 3 8B GPTQ directly into GPU memory on startup (~5.5GB VRAM, 30-90s cold start). In v2.2.0 this is fully removed.

**New flow:**
1. `generate_chat_input()` formats the prompt using the hardcoded Llama 3 Instruct chat template (no tokenizer needed)
2. `llm_client.generate()` POSTs to `https://api.runpod.ai/v2/{ENDPOINT_ID}/runsync`
3. RunPod worker runs the GPTQ model and returns `{"generated_text": "..."}`
4. Backend processes the response and returns to the frontend

**Benefits:**
- Backend server starts in seconds (no model loading)
- No GPU required on the API server
- RunPod scales to zero when idle (cost-efficient)
- VRAM managed by RunPod infrastructure

### RunPod Serverless Handler (`runpod-handler/`)

New directory containing the RunPod worker:

| File | Purpose |
|---|---|
| `runpod-handler/handler.py` | Worker entry point — loads model from network volume on cold start, handles inference requests |
| `runpod-handler/requirements.txt` | Worker dependencies (runpod, torch, transformers, auto-gptq, etc.) |
| `runpod-handler/Dockerfile` | Container definition (base: `runpod/pytorch:2.1.0-py3.10-cuda11.8.0-devel`) |

**Model loading strategy:** On cold start, checks `MODEL_PATH` env var (default `/workspace/models/llama3-8b-gptq`). If the path is empty, downloads `MaziyarPanahi/Meta-Llama-3-8B-Instruct-GPTQ` from HuggingFace via `snapshot_download`. Subsequent cold starts reuse the cached files from the network volume.

**Handler input schema:**
```json
{
  "input": {
    "prompt": "<formatted chat string>",
    "max_new_tokens": 60,
    "temperature": 0.7,
    "do_sample": true,
    "top_k": 50
  }
}
```

**Handler output:** `{"generated_text": "..."}` or `{"error": "..."}` on failure.

### LLM Client (`backend/llm_client.py`)

New module — thin async wrapper around the RunPod runsync API:

```python
await llm_client.generate(prompt, max_new_tokens=60, temperature=0.7, do_sample=True, top_k=50)
# Returns: str (the generated text)
```

- 120-second timeout
- Raises `RuntimeError` on HTTP errors, missing credentials, or inference failures
- Reads `RUNPOD_API_KEY` and `RUNPOD_ENDPOINT_ID` from environment

### MongoDB Atlas Migration

Database moved from local Docker container (`mongodb://mongodb:27017`) to Atlas (`mongodb+srv://...`).

- Connection string in `MONGO_URL` environment variable
- Password masked in startup logs via regex substitution
- Seed scripts (`backend/scripts/seed_a1_*.py`) read from `MONGO_URL` — no localhost fallback
- `docker-compose.yml` MongoDB `depends_on` commented out (not needed when using Atlas)
